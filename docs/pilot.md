# Пилот в школе: установка на Ubuntu Server без HTTPS

Руководство для ИТ-специалиста школы и ответственного за пилот. Цель — за 2–3 недели проверить дневник
на небольшой группе: один администратор, два-три учителя, несколько учеников. Задача пилота — найти ошибки
и неудобства до того, как дневником начнёт пользоваться вся школа.

Пилот работает по обычному HTTP внутри школьной сети. Это осознанное упрощение на время теста, у него есть
правила — раздел 1. Для постоянной работы нужен HTTPS: [installation.md](installation.md), [https.md](https.md).

| Раздел | Кто делает | Сколько времени |
| --- | --- | --- |
| 2–5. Подготовка, установка, сеть | ИТ-специалист | 1–2 часа |
| 6. Первый вход и настройка школы | системный администратор, затем администратор | 1–2 часа |
| 7. Резервные копии | ИТ-специалист | 20 минут |
| 8–9. Пилот и обратная связь | все участники | 2–3 недели |
| 10–12. Обслуживание, диагностика, завершение | ИТ-специалист | по необходимости |

## 1. Правила пилота по HTTP

По HTTP логины, пароли и оценки идут по сети открытым текстом. Любой компьютер в той же сети может их
перехватить. Поэтому на время пилота:

1. **Дневник доступен только из школьной сети.** Никакого проброса порта в интернет. Доступ ограничен
   сегментами учителей и учеников (раздел 5). Гостевой Wi-Fi дневник не видит.
2. **Пароли дневника — только для дневника.** Участники не используют пароль от почты, Госуслуг и других
   сервисов. Предупредите их об этом при выдаче учётных записей.
3. **Минимум персональных данных учеников.** Ученики — несовершеннолетние. Заводите их под именем и
   первой буквой фамилии («Анна К.») или под псевдонимом. Родителей участников предупредите о тесте; если
   в школе принято письменное согласие, возьмите его.
4. **Официальный журнал на время пилота остаётся прежним** (бумажный или текущая система). Оценки в пилоте
   — тестовые или дублирующие, решения по ним не принимаются.
5. **После пилота все пароли меняются** — они передавались без шифрования (раздел 12).

## 2. Что подготовить

**Сервер.** Ubuntu Server 24.04 LTS (на Debian 12 отличается только репозиторий Docker).

| | Минимум для пилота | Рекомендуется |
| --- | --- | --- |
| Процессор | 2 ядра | 4 ядра |
| Память | 4 ГБ | 8 ГБ |
| Диск | 20 ГБ SSD | 50 ГБ SSD |
| Сеть | статический IP в школьной сети | отдельный сегмент для серверов |

**Сеть.** Запишите заранее:

- IP-адрес сервера — дальше в примерах `192.168.10.20`;
- сети, из которых участники будут открывать дневник: компьютеры учителей и Wi-Fi, к которому подключены
  телефоны учеников. Пример — `10.10.20.0/24` и `10.10.30.0/24`;
- сеть, из которой ИТ-специалист заходит на сервер по SSH, — пример `10.10.10.0/24`.

**Интернет на время установки.** Дневник собирается на самом сервере из исходников, поэтому серверу нужен
исходящий доступ к `github.com` (код), `download.docker.com` и Docker Hub (Docker и базовые образы),
`gcr.io` (образ для сервера), `registry.npmjs.org` (интерфейс) и `proxy.golang.org` (модули Go). После сборки
дневник работает без интернета; доступ снова понадобится для обновлений.

**Люди.**

| Роль в дневнике | Кто | Сколько |
| --- | --- | --- |
| Системный администратор | ИТ-специалист или ответственный за пилот | 1 |
| Администратор | сотрудник, который будет заводить пользователей и расписание | 1 |
| Учитель (один из них — классный руководитель) | учителя-участники | 2–3 |
| Ученик | ученики одного класса | 3–8 |
| Родитель (по желанию) | родители учеников-участников | 1–3 |

**Куда кладутся копии.** Второй диск, сетевое хранилище или другой сервер — не тот же диск, что у дневника.
Для пилота допустим внешний USB-диск, который раз в неделю уносят.

## 3. Установка

Два способа — выберите один:

| | Docker (этот раздел) | Без Docker — [native-install.md](native-install.md) |
| --- | --- | --- |
| PostgreSQL | в контейнере, отдельно не ставится | PostgreSQL 17 из официального репозитория, служба системы |
| Сборка | `docker compose` собирает образы на сервере | Go и Node.js на сервере, сборка командами |
| Службы | контейнеры, `docker compose ps` | systemd, `systemctl status` |
| Обновление | `git checkout` + `docker compose build` | `git checkout` + пересборка + `systemctl restart` |
| Когда выбрать | по умолчанию: меньше ручной работы | Docker на сервере нельзя или не нужен |

Разделы 1, 2, 4, 6, 8, 9 и 12 общие для обоих способов. Для установки без Docker разделы 3, 5, 7, 10 и 11
этого документа заменяет [native-install.md](native-install.md).

**PostgreSQL в способе с Docker отдельно не устанавливается:** он работает в контейнере `postgres` из того же
`docker-compose.yml`, его данные лежат в томе Docker, порт наружу не открыт. Пароль базы генерируется в `.env`
(шаг 3.4), вводить его нигде не нужно.

**Пилот начинается с пустой базы.** Тестовые данные не нужны и не устанавливаются: при первом запуске создаются
только таблицы, первая учётная запись — системный администратор (раздел 6.1), дальше школа заводится с нуля
через интерфейс. Демо-набор (`seed`) на сервере с `APP_ENV=production` запустить нельзя — утилита откажется.

Все команды выполняются на сервере под пользователем с правами `sudo`.

### 3.1. Система и время

```bash
sudo apt-get update && sudo apt-get -y upgrade
sudo apt-get install -y ca-certificates curl git openssl rsync
sudo timedatectl set-timezone Europe/Moscow    # часовой пояс школы
timedatectl status                             # должно быть «System clock synchronized: yes»
```

Точное время важно: от него зависят «сегодня» в дневнике, сроки заданий и срок сессий.

### 3.2. Docker

Docker Engine и Compose ставятся из официального репозитория Docker, не из репозитория Ubuntu:

```bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" |
  sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
docker compose version     # 2.24 или новее
sudo systemctl enable --now docker
```

Не добавляйте пользователей в группу `docker`: это равносильно правам root. Команды ниже — через `sudo`.

### 3.3. Код

```bash
sudo git clone https://github.com/klezufa/schooldiarysvu.git /opt/schooldiary
cd /opt/schooldiary
sudo git checkout "$(sudo git tag -l 'pilot-*' --sort=-v:refname | head -1)"   # последний выпуск пилота, а не случайный коммит из main
```

В репозитории всё, что нужно серверу: `docker-compose.yml`, Dockerfile сервера и интерфейса, настройки Nginx
(`deploy/nginx`), миграции базы, скрипты копирования и восстановления (`scripts/`). Готовых образов и сборок
скачивать не нужно — `docker compose` соберёт их на шаге 3.5. Не хватает только `.env` с настройками этого
сервера: его вы создадите на следующем шаге, в git он не хранится.

### 3.4. Настройки

Файл `/opt/schooldiary/.env` создаётся один раз. Права — только root, в git он не попадает.
Замените `192.168.10.20` на IP своего сервера:

```bash
cd /opt/schooldiary
sudo install -m 600 /dev/null .env
sudo tee .env >/dev/null <<EOF
APP_ENV=production
# Профиль без шифрования — только для пилота (docs/pilot.md, раздел 1).
NETWORK_PROFILE=local-http
SESSION_COOKIE_SECURE=false
# Только шестнадцатеричные символы: пароль подставляется в адрес базы.
POSTGRES_PASSWORD=$(openssl rand -hex 24)
SCHOOL_TIMEZONE=Europe/Moscow
# IP сервера в школьной сети: дневник слушает только этот адрес.
BIND_ADDR=192.168.10.20
# Порт 80 — чтобы адрес был без номера порта: http://192.168.10.20
HTTP_PORT=80
EOF
sudo cat .env    # проверьте IP и что пароль базы сгенерировался
```

Пароль базы вводить нигде не нужно: скрипты обращаются к ней изнутри контейнера. Не меняйте его после
первого запуска — база уже создана с этим паролем.

### 3.5. Запуск

```bash
cd /opt/schooldiary
sudo docker compose config --quiet && echo "конфигурация в порядке"
sudo DIARY_VERSION="$(git describe --tags --always)" docker compose up -d --build   # первая сборка — 5–15 минут
sudo docker compose ps        # postgres, backend, worker, nginx — running (healthy)
curl -fsS http://192.168.10.20/health/ready ; echo     # {"status":"ready"}
```

При первом запуске PostgreSQL создаёт пустую базу, а backend — таблицы в ней (миграции встроены в программу
и применяются при каждом запуске). Контейнеры поднимаются сами после перезагрузки
сервера (`restart: unless-stopped`) — проверьте это один раз: `sudo reboot`, затем снова `docker compose ps`.

## 4. Имя вместо IP (необязательно)

Участникам удобнее `http://dnevnik.svu`, чем IP. Если в школе есть свой DNS (AdGuard Home, роутер, контроллер
домена), добавьте запись `dnevnik.svu → 192.168.10.20` — см. [adguard-home.md](adguard-home.md). Без DNS
пользуйтесь IP-адресом. На телефоне адрес удобно добавить на главный экран: «Поделиться» → «На экран
"Домой"» (iPhone) или меню → «Добавить на главный экран» (Android).

## 5. Сеть и firewall

Docker публикует порты в обход `ufw`: правило `ufw deny 80` дневник **не закроет**. Поэтому SSH
ограничивается через `ufw`, а доступ к дневнику — через цепочку `DOCKER-USER` (подробно — [network.md](network.md)).

**SSH — только из сети ИТ:**

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 10.10.10.0/24 to any port 22 proto tcp
sudo ufw enable
```

**Дневник — только из сетей участников.** Скрипт `/usr/local/sbin/schooldiary-firewall.sh` (замените
интерфейс и сети на свои; интерфейс — команда `ip -br addr`):

```bash
sudo tee /usr/local/sbin/schooldiary-firewall.sh >/dev/null <<'EOF'
#!/bin/sh
set -eu
IF=ens18
iptables -F DOCKER-USER
iptables -A DOCKER-USER -i "$IF" -m conntrack --ctstate RELATED,ESTABLISHED -j RETURN
for net in 10.10.10.0/24 10.10.20.0/24 10.10.30.0/24; do
  iptables -A DOCKER-USER -i "$IF" -s "$net" -j RETURN
done
iptables -A DOCKER-USER -i "$IF" -j DROP
iptables -A DOCKER-USER -j RETURN
EOF
sudo chmod 700 /usr/local/sbin/schooldiary-firewall.sh
```

Правила `DOCKER-USER` пропадают при перезагрузке, поэтому их применяет служба после запуска Docker:

```bash
sudo tee /etc/systemd/system/schooldiary-firewall.service >/dev/null <<'EOF'
[Unit]
Description=Firewall rules for School Diary published ports
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/usr/local/sbin/schooldiary-firewall.sh

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now schooldiary-firewall
```

Если в школе есть VLAN, главный рубеж — ACL на маршрутизаторе: разрешить TCP 80 до сервера только
нужным сегментам. Правила на сервере — второй рубеж.

**Проверка:** с компьютера учителя `http://192.168.10.20` открывается; с телефона в гостевом Wi-Fi —
не открывается (таймаут).

## 6. Первый вход и настройка школы

### 6.1. Системный администратор

Первая учётная запись создаётся утилитой на сервере. Пароль вводится без отображения и не попадает
в историю команд:

```bash
cd /opt/schooldiary
read -rsp 'Пароль системного администратора (от 12 символов): ' BOOTSTRAP_ADMIN_PASSWORD; echo
export BOOTSTRAP_ADMIN_PASSWORD
sudo -E docker compose run --rm --no-deps \
  -e BOOTSTRAP_ADMIN_LOGIN=sysadmin -e BOOTSTRAP_ADMIN_DISPLAY_NAME='Системный администратор' -e BOOTSTRAP_ADMIN_PASSWORD \
  --entrypoint /app/bootstrap-admin backend
unset BOOTSTRAP_ADMIN_PASSWORD
```

Повторный запуск откажется работать, если системный администратор уже есть. Демо-данные (`seed`) на этом
сервере не запускаются: утилита работает только при `APP_ENV=development`.

Войдите как `sysadmin` по адресу `http://192.168.10.20`. Предупреждение о незашифрованном соединении на
странице — ожидаемо, это пилот. Проверьте страницу **«Система»**: все сервисы в норме, профиль `local-http`.

### 6.2. Настройка школы

В разделе **«Администрирование»** откроется простой режим с карточкой **«Подготовка школы»**. Шаги идут по
порядку, следующий подсвечен:

1. Учебный год и четверти.
2. Классы — для пилота достаточно одного.
3. Предметы — из типового списка.
4. Учителя — сразу с предметами и классами; одного назначьте классным руководителем.
5. Ученики — сразу с классом; родителя можно добавить в той же форме.
6. Расписание — уроки ставятся в клетки недели, дневник сам создаёт уроки на четверть.

Администратора для пилота заведите там же: **«Расширенный режим» → «Пользователи» → «Добавить
пользователя»**, роль «Администратор». Дальше пользователей заводит он.

### 6.3. Выдача учётных записей

- Логин дневник предлагает сам по ФИО. **Временный пароль показывается один раз** — сразу перепишите его.
- Выдавайте лично, на бумажке, каждому участнику свой. Не рассылайте пароли в чатах.
- При первом входе дневник попросит придумать свой пароль: не короче 12 символов, только для дневника
  (раздел 1).
- Забытый пароль администратор сбрасывает: **«Администрирование» → «Пароли и вход»**.

## 7. Резервные копии

Пилот — тоже данные: потерять неделю отметок учителей неприятно. Настройте копирование до начала пилота.

```bash
sudo tee /etc/default/schooldiary >/dev/null <<'EOF'
BACKUP_DIR=/var/backups/schooldiary
BACKUP_KEEP=14
# Вторая копия на другом носителе: смонтированный каталог или user@host:/path (rsync по SSH-ключу root).
BACKUP_REMOTE=/mnt/backup/schooldiary
EOF
sudo chmod 600 /etc/default/schooldiary
sudo chmod +x /opt/schooldiary/scripts/*.sh

sudo tee /etc/cron.d/schooldiary >/dev/null <<'EOF'
SHELL=/bin/bash
# Ежедневно в 02:30. С --quiesce дневник недоступен 10–60 секунд, зато база и файлы строго согласованы.
30 2 * * * root set -a; . /etc/default/schooldiary; /opt/schooldiary/scripts/backup.sh --quiesce >/dev/null 2>>/var/log/schooldiary-cron.log
EOF
```

Первая копия — вручную, сразу:

```bash
sudo bash -c 'set -a; . /etc/default/schooldiary; /opt/schooldiary/scripts/backup.sh'
ls -l /var/backups/schooldiary
```

Итог каждой копии виден системному администратору: **«Система» → «Эксплуатация»** — дата, размер, ошибка
последней неудачной попытки. **Хотя бы раз за пилот проверьте восстановление** по
[backup-restore.md](backup-restore.md): копия без проверенного восстановления — это надежда, а не копия.

## 8. План пилота

### Неделя 0 — подготовка (1–2 дня)

- [ ] Сервер установлен, `docker compose ps` — всё `healthy`, перезагрузка проверена.
- [ ] Firewall: из гостевой сети дневник не открывается.
- [ ] Первая резервная копия есть.
- [ ] Школа настроена (раздел 6.2), расписание на две недели вперёд видно у учителя и ученика.
- [ ] Участникам выданы учётные записи и коротко рассказано, что тестируем и куда писать (раздел 9).

### Неделя 1 — основные сценарии

Каждый участник выполняет свой список хотя бы по разу, а дальше пользуется дневником как обычно.

**Учитель:**
- [ ] Войти с компьютера и с телефона, сменить временный пароль.
- [ ] Открыть урок из «Главной» или «Расписания», заполнить тему.
- [ ] Отметить посещаемость: «Все присутствуют», затем исключения.
- [ ] Добавить работу и выставить оценки в журнале: мышью и с клавиатуры (цифра → Enter).
- [ ] Исправить оценку и посмотреть её историю.
- [ ] Выдать домашнее задание с файлом.
- [ ] Классный руководитель: «Мой класс», отчёт по классу.
- [ ] Пройти урок с телефона: журнал «по уроку».

**Ученик:**
- [ ] Войти с телефона, сменить пароль.
- [ ] Найти расписание на неделю, открыть урок и его задание.
- [ ] Скачать файл задания, отметить задание выполненным.
- [ ] Увидеть новую оценку и уведомление о ней.

**Родитель (если участвует):**
- [ ] Увидеть оценки, посещаемость и задания своего ребёнка.
- [ ] С двумя детьми — переключиться между ними.

**Администратор:**
- [ ] Добавить ученика, перевести его в другой класс, сбросить пароль.
- [ ] Изменить урок в расписании; назначить замену заболевшему учителю (плитка «Замены»).
- [ ] Отправить объявление классу.
- [ ] Сформировать архив журнала класса и распечатать его или сохранить в PDF.

**Системный администратор:**
- [ ] Каждый день: «Система» — сервисы в норме, ночная копия прошла.

### Неделя 2 — обычная работа

Учителя ведут дневник параллельно с основным журналом, ученики заходят сами. Это главная проверка: не
сценарий по списку, а повседневное использование. Отдельно попробуйте:

- наплыв — все ученики класса входят одновременно в начале урока;
- слабый Wi-Fi — в дальнем кабинете, на перемене;
- разные устройства — старый Android, iPhone, школьный компьютер, планшет;
- тёмную тему и «Поиск и переходы» (Ctrl+K) на компьютере.

### Неделя 3 (необязательно) — исправления

Выпуск с исправлениями ставится по разделу 10.3, после чего участники перепроверяют то, на что жаловались.

### Итоговая встреча

20–30 минут с участниками: что мешало, чего не хватило, что понравилось. Итоги — в один документ, решение
о запуске для всей школы — по критериям из раздела 12.

## 9. Сбор обратной связи

Договоритесь об одном канале — общий документ, таблица или чат пилота. Каждое сообщение по форме:

| Поле | Пример |
| --- | --- |
| Кто и в какой роли | Учитель математики |
| Устройство и браузер | Телефон Android, Chrome |
| Где | Журнал, 7Б, алгебра |
| Что делал | Выставил оценку, нажал Enter |
| Что ожидал | Оценка сохранится, курсор перейдёт ниже |
| Что произошло | Оценка пропала после обновления страницы |
| Код запроса | `a1b2c3…` (если дневник показал ошибку) |
| Скриншот | по возможности |
| Насколько мешает | блокирует / мешает / мелочь / пожелание |

**Код запроса.** Если дневник показывает ошибку, внизу сообщения есть «Код запроса». По нему ИТ-специалист
находит запись в журнале сервера (раздел 11) — это самый быстрый способ разобрать ошибку.

Раз в 2–3 дня ответственный за пилот разбирает сообщения:

| Категория | Что делать |
| --- | --- |
| Блокирует работу | исправить в течение 1–2 дней, обновить сервер |
| Мешает | исправить до конца пилота |
| Мелочь, пожелание | в список на будущее |
| Ошибка пользователя | улучшить подсказку или памятку |

## 10. Обслуживание во время пилота

### 10.1. Ежедневно (5 минут)

```bash
cd /opt/schooldiary
sudo docker compose ps              # все сервисы running (healthy)
df -h / /var/backups                # свободное место
ls -lt /var/backups/schooldiary | head -3   # ночная копия на месте
```

Или страница «Система» под системным администратором.

### 10.2. Перезапуск

```bash
cd /opt/schooldiary
sudo docker compose restart backend worker    # приложение, база не трогается
sudo docker compose up -d                     # поднять всё, что остановлено
```

### 10.3. Обновление на исправленную версию

Вне уроков. Копия — непосредственно перед обновлением:

```bash
cd /opt/schooldiary
sudo bash scripts/backup.sh --quiesce --label pre-update
sudo git fetch --tags
sudo git checkout "$(sudo git tag -l 'pilot-*' --sort=-v:refname | head -1)"   # самый новый выпуск пилота
sudo DIARY_VERSION="$(git describe --tags --always)" docker compose build --pull
sudo docker compose up -d
sudo docker compose ps
```

После обновления: «Система» показывает новую версию, учитель открывает журнал, ученик — расписание.

**Откат** — только вместе с данными, к копии `pre-update`; всё внесённое после обновления потеряется.
Порядок — [update.md](update.md#откат).

## 11. Диагностика

| Симптом | Что проверить |
| --- | --- |
| Дневник не открывается ни у кого | `sudo docker compose ps`; `curl -fsS http://192.168.10.20/health/ready` на самом сервере |
| С сервера открывается, у участников — нет | firewall (раздел 5), ACL на маршрутизаторе, верный ли `BIND_ADDR` в `.env` |
| Открывается с компьютеров, но не с телефонов | телефоны в гостевом Wi-Fi или в сегменте, которого нет в списке сетей |
| «Слишком много попыток» при входе | защита от перебора: подождать указанное время; администратор может сбросить пароль |
| Ошибка с кодом запроса | `sudo docker compose logs backend --since 24h \| grep КОД` |
| После перезагрузки не поднялся | `sudo systemctl status docker`, затем `sudo docker compose up -d` |
| Закончилось место | `df -h`; старые копии в `/var/backups/schooldiary`; `sudo docker system prune` удаляет неиспользуемые образы |

Журналы:

```bash
cd /opt/schooldiary
sudo docker compose logs backend --since 1h      # запросы и ошибки сервера (JSON, без паролей)
sudo docker compose logs worker --since 1h       # фоновые задачи: уведомления, очистка сессий
sudo docker compose logs nginx --since 1h
```

Больше случаев — [troubleshooting.md](troubleshooting.md).

## 12. Завершение пилота

### Критерии готовности к работе всей школы

- [ ] Нет открытых замечаний категории «блокирует», замечания «мешает» исправлены или осознанно отложены.
- [ ] Учителя пилота готовы вести только электронный журнал.
- [ ] Ночные копии шли каждый день, восстановление проверено хотя бы раз.
- [ ] Решены вопросы с персональными данными: положение школы, согласия, кто имеет доступ.
- [ ] Выбран способ HTTPS: внутренний центр сертификации или публичный домен ([https.md](https.md)).
- [ ] Решено, нужен ли доступ из дома для учеников и родителей: он требует публичного адреса и HTTPS.

### Вариант А — продолжить на этом сервере с HTTPS

1. Копия: `sudo bash scripts/backup.sh --quiesce --label pre-https`.
2. Получить и установить сертификат — [https.md](https.md) и [installation.md](installation.md), раздел 4.
3. В `.env` удалить строки `NETWORK_PROFILE`, `SESSION_COOKIE_SECURE` и `HTTP_PORT` и добавить
   `DIARY_HOSTNAME`, `TLS_DIR` и `COMPOSE_FILE=docker-compose.yml:docker-compose.https.yml` — как в
   [installation.md](installation.md), раздел 3. Затем `sudo docker compose up -d` и проверка из раздела 8 того же документа.
4. **Сбросить пароли всем участникам пилота** и завершить их сеансы: «Администрирование» → «Пользователи»,
   кнопки сброса пароля и «Завершить все сеансы». Пароли передавались без шифрования.
5. Добавить в `/etc/cron.d/schooldiary` продление сертификата, если он от Let's Encrypt ([installation.md](installation.md), раздел 7).

### Вариант Б — начать с чистой базы

Если данные пилота не нужны: сделайте копию на память, затем `sudo docker compose down -v` (удаляет **все**
данные дневника) и установите систему заново по [installation.md](installation.md) — сразу с HTTPS.
