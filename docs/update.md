# Обновление

Обновление занимает несколько минут простоя: пересборка образов, перезапуск, применение миграций базы при
запуске backend. Делайте его вне учебного времени и всегда с резервной копией непосредственно перед началом.

## Порядок

```bash
cd /opt/schooldiary

# 1. Что меняется: описание выпуска (Releases на GitHub) и список коммитов до нового тега.
sudo git fetch --tags
git log --oneline HEAD..<новый тег>

# 2. Согласованная копия перед обновлением (хранится отдельно от ежедневных: метка pre-update).
sudo bash scripts/backup.sh --quiesce --label pre-update

# 3. Новый код и образы. DIARY_VERSION попадёт на страницу «Система».
sudo git checkout <новый тег>
sudo DIARY_VERSION="$(git describe --tags --always)" docker compose build --pull

# 4. Перезапуск: backend применит миграции, worker и nginx дождутся его готовности.
sudo docker compose up -d
sudo docker compose ps
```

Проверка после обновления:

1. `sudo docker compose ps` — все сервисы `running (healthy)`; `sudo docker compose logs backend --since 10m`
   без ошибок миграций.
2. Страница «Система»: версия — новый тег, сервисы в норме.
3. Вход учителя, журнал класса, расписание; вход ученика или родителя.
4. Ночная резервная копия следующего дня прошла (запись на «Системе»).

## Откат

Миграции применяются только вперёд: после запуска новой версии база уже в новой схеме, и прежний код её
не примет. Откат — это возврат кода **и** данных к копии `pre-update`:

```bash
cd /opt/schooldiary
sudo git checkout <прежний тег>
sudo DIARY_VERSION="$(git describe --tags --always)" docker compose build
sudo bash scripts/restore.sh /opt/schooldiary/backups/pre-update-ГГГГММДД-ЧЧММСС
```

`restore.sh` проверит, что схема копии не новее кода, и запустит прежнюю версию на прежних данных. Всё, что
пользователи внесли между обновлением и откатом, будет потеряно — поэтому решение об откате принимайте сразу
после проверки, а не через день. Файлы `*.down.sql` в `db/migrations` предназначены для разработки; в production
их не применяйте: они удаляют таблицы и столбцы вместе с данными.

## Базовые образы и система

- **Образы** (`postgres:17.x-alpine`, `nginx-unprivileged`, `golang`, `node`) обновляются вместе с выпуском дневника:
  `build --pull` подтягивает исправления безопасности тех же версий. Dependabot в репозитории предлагает новые версии.
- **PostgreSQL 17 → 18** (смена мажорной версии) не делается заменой тега: формат данных несовместим. Процедура —
  копия, новый пустой том, запуск новой версии, `restore.sh`; выполняйте её как отдельную плановую работу.
- **Ubuntu**: включите `unattended-upgrades` для исправлений безопасности. Обновление Docker Engine перезапускает
  контейнеры; они поднимутся сами (`restart: unless-stopped`).
- **Сертификат** обновляется независимо от версии дневника ([https.md](https.md)).
