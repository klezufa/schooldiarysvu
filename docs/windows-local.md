# Школьный дневник на Windows 11: локальный запуск для тестирования

Руководство для одного ноутбука с Windows 11. Все команды в этом документе были выполнены на Windows 11 Pro (PowerShell 5.1, Docker Desktop 29, Node.js 24, Go 1.26.10, PostgreSQL 17/18) — см. раздел «Что проверено».

> **Это тестовый режим, а не защищённая эксплуатация.** Используется профиль `local-http`: соединение не шифруется. Сервер по умолчанию слушает только `127.0.0.1` (виден лишь с этого ноутбука). Не загружайте реальные персональные данные учеников и не открывайте доступ из сети без осознанного решения (см. раздел 9).

Есть два способа запуска. Выберите один:

| | Способ А — без Docker (рекомендуется) | Способ Б — Docker Desktop |
|---|---|---|
| Что запускается | PostgreSQL (отдельный кластер в `.local\`) + `server.exe` + `worker.exe` | PostgreSQL, backend, worker, Nginx в контейнерах |
| Права администратора | не нужны | нужны для установки Docker Desktop |
| Похоже на школьный сервер | частично | да (те же образы и Nginx, что в эксплуатации) |
| Адрес по умолчанию | http://127.0.0.1:8090 | http://127.0.0.1:8080 (меняется `HTTP_PORT`) |
| Управление | `deploy\windows\diary.cmd` | `docker compose` + `deploy\windows\docker-data.cmd` |

Данные способов А и Б **независимы** — это разные базы.

---

## 1. Что понадобится

- Windows 11, 8 ГБ ОЗУ и 5 ГБ свободного диска (Docker — ещё около 3 ГБ на образы).
- Интернет для установки программ и сборки (после сборки система работает офлайн).
- Программы (откройте **PowerShell** и проверьте, что уже есть):

```powershell
git --version
node --version      # нужен Node.js 22 или новее (проверено на 24)
go version          # нужен Go 1.26 или новее (go.mod закрепляет исправленный toolchain 1.26.10)
```

Чего нет — установите (каждая команда ставит программу для текущего пользователя или спрашивает разрешение):

```powershell
winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id GoLang.Go -e
winget install --id PostgreSQL.PostgreSQL.17 -e   # способ А: нужны только файлы программы
```

После установки **закройте и снова откройте PowerShell**, чтобы обновился PATH.

PostgreSQL для способа А: мастер установки попросит пароль суперпользователя и создаст службу Windows — **ни то ни другое для дневника не используется**. Скрипт запускает собственный кластер в папке проекта на порту 55440 и не трогает вашу службу. Если PostgreSQL установлен в нестандартную папку, задайте `$env:DIARY_PG_BIN = 'D:\путь\PostgreSQL\17\bin'`.

Для способа Б нужен **Docker Desktop** (https://www.docker.com/products/docker-desktop/): `winget install --id Docker.DockerDesktop -e`, затем запустите его и дождитесь состояния «Engine running».

## 2. Получить код

```powershell
cd $HOME
git clone https://github.com/klezufa/schooldiarysvu.git
cd schooldiarysvu
```

Репозиторий приватный: при первом обращении Git Credential Manager откроет браузер для входа в GitHub. Дальше все команды выполняются **из корня репозитория**.

## 3. Способ А: запуск без Docker

Все команды — через обёртку `deploy\windows\diary.cmd` (она запускает PowerShell-скрипт с разрешением выполнения только для этого запуска; политика выполнения скриптов в системе не меняется).

### 3.1. Проверить инструменты

```powershell
deploy\windows\diary.cmd doctor
```

Скрипт ищет Go, Node.js/npm и программы PostgreSQL (`initdb`, `pg_ctl`, `psql`, `pg_dump`, `pg_restore`) в PATH, в `C:\Program Files\PostgreSQL\*\bin`, в `.tools\` и в `DIARY_PG_BIN`. Для каждого отсутствующего инструмента выводится команда установки. Все строки должны быть `[ok]`.

### 3.2. Установка (один раз, 3–6 минут)

```powershell
deploy\windows\diary.cmd setup
```

Что происходит:

1. Создаётся папка `.local\` (в `.gitignore`, доступ только вашей учётной записи) и файл `.local\config.env` со случайным паролем базы данных.
2. Собирается интерфейс (`npm ci` — только если зависимости изменились — и `npm run build`).
3. Собираются `server.exe`, `worker.exe`, `seed.exe`, `bootstrap-admin.exe` в `.local\bin\`.
4. Создаётся отдельный кластер PostgreSQL в `.local\pgdata\` (аутентификация `scram-sha-256`, только `127.0.0.1:55440`) и база `diary`.

Повторный запуск `setup` безопасен: существующие данные сохраняются. Он же применяется после `git pull` (останавливает приложение, пересобирает, база остаётся).

### 3.3. Запуск

```powershell
deploy\windows\diary.cmd start
```

Скрипт запускает PostgreSQL, затем `server.exe` (он при старте сам применяет миграции) и `worker.exe`, и ждёт, пока `/health/ready` ответит `200`. В конце — адрес: **http://127.0.0.1:8090/**.

### 3.4. Создать пользователей (выберите вариант)

**Вариант 1. Демонстрационные данные** (быстрее всего для проверки): класс 5А/5Б, предметы, расписание, уроки, оценки, посещаемость, задание, объявление и 11 пользователей.

```powershell
deploy\windows\diary.cmd seed-demo          # базовый набор (на нём рассчитаны автотесты)
deploy\windows\diary.cmd seed-demo -Rich    # расширенный: 25 учеников, 5 учителей, 7 предметов, полное расписание,
                                             # ~3000 оценок и посещаемость с 1 сентября — чтобы графики дашбордов были наполнены
```

Скрипт спросит временный пароль (скрытый ввод, не менее 12 символов) — он будет у **всех** демо-пользователей. При первом входе система потребует сменить его.

| Логин | Роль |
|---|---|
| `demo-sysadmin` | системный администратор: учебные годы и периоды, шкалы, настройки школы, выдача прав администратора, страница «Система» |
| `demo-admin` | администратор: пользователи и роли, импорт, приглашения, зачисление, назначения, расписание, классы и предметы |
| `demo-teacher1` | учитель математики и классный руководитель 5А |
| `demo-teacher2` | учитель русского языка |
| `demo-student1` … `demo-student5` | ученики |
| `demo-parent1` | родитель двух детей (`demo-student1`, `demo-student2`) |
| `demo-parent2` | родитель `demo-student3` |
| `demo-teacher3` … `demo-teacher5`, `demo-student6` … `demo-student25` | только в наборе `-Rich` |

Сегодня может идти только что начавшийся учебный период, в котором ещё нет оценок. Тогда дашборды предложат кнопку «Показать: I четверть»; период можно выбрать и вручную в шапке дашборда.

**Вариант 2. Только системный администратор** (чистая система, данные вводите вручную через раздел «Администрирование»):

```powershell
deploy\windows\diary.cmd create-admin
```

Скрипт спросит логин, имя и временный пароль и создаст **системного администратора** — первого человека с полным доступом. Он настраивает учебный год и периоды, а обычных администраторов (которые заводят пользователей и назначают роли) создаёт в «Администрирование → Пользователи» или выдаёт им приглашение. Демо-учётные записи при этом **не создаются**. Если в базе уже есть системный администратор, команда откажется работать.

> Для автоматизации (без интерактивного ввода) пароли можно передать переменными окружения `DIARY_DEMO_PASSWORD`, `DIARY_ADMIN_LOGIN`, `DIARY_ADMIN_NAME`, `DIARY_ADMIN_PASSWORD`. Не сохраняйте их в профиле PowerShell.

### 3.5. Открыть дневник

Откройте http://127.0.0.1:8090/ в браузере, войдите (например, `demo-teacher1` с временным паролем), задайте новый пароль (не менее 12 символов).

> **Совет по демо-данным.** Уроки и оценки демо-набора относятся к сентябрю 2026 (учебный период «I четверть»). В «Журнале» выберите **Период: I четверть** и **Месяц: 2026-09**; в «Расписании» перейдите кнопкой «‹» на недели сентября. Если сегодняшнего урока нет, «Сегодня» покажет «На сегодня уроки закончились» — это ожидаемо.

### 3.6. Управление

```powershell
deploy\windows\diary.cmd status     # что запущено, адрес, /health/ready
deploy\windows\diary.cmd logs       # последние строки журналов
deploy\windows\diary.cmd stop       # остановить приложение и PostgreSQL
deploy\windows\diary.cmd start      # запустить снова (данные сохраняются)
deploy\windows\diary.cmd restart    # перезапустить server и worker
```

Журналы: `.local\logs\server.log` (JSON, одна строка на запрос: `status`, `duration_ms`, `request_id`), `server.err.log`, `worker.log`, `postgres.log`. Пароли и тела запросов в журнал не пишутся.

### 3.7. Обновление до новой версии

```powershell
deploy\windows\diary.cmd backup -Quiesce      # сначала копия (раздел 5)
git pull
deploy\windows\diary.cmd setup
deploy\windows\diary.cmd start
```

Миграции базы применяются автоматически при старте сервера.

### 3.8. Настройки (`.local\config.env`)

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `DIARY_HTTP_PORT` | `8090` | порт сайта |
| `DIARY_PG_PORT` | `55440` | порт приватного PostgreSQL |
| `DIARY_BIND_ADDR` | `127.0.0.1` | на каком адресе слушает сервер (см. раздел 9) |
| `DIARY_BACKUP_KEEP` | `14` | сколько копий хранить |
| `SCHOOL_TIMEZONE` | `Europe/Moscow` | часовой пояс школы |

Если порт занят, измените значение и выполните `restart`. `POSTGRES_PASSWORD` не меняйте вручную: он совпадает с паролем в кластере.

## 4. Способ Б: Docker Desktop

Запускайте Docker Desktop и дождитесь «Engine running». Команды — в PowerShell из корня репозитория.

### 4.1. Секреты и настройки

Создайте `.env` (он в `.gitignore`) со случайным паролем базы:

```powershell
$bytes = New-Object byte[] 18
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$password = [Convert]::ToBase64String($bytes) -replace '[+/=]', ''
Set-Content -Path .env -Encoding ascii -Value @("POSTGRES_PASSWORD=$password", 'HTTP_PORT=8088')
```

`HTTP_PORT=8088` — чтобы не конфликтовать с другими программами на 8080. По умолчанию Nginx привязан к `127.0.0.1` (переменная `BIND_ADDR`); PostgreSQL наружу не публикуется вообще.

### 4.2. Сборка и запуск

```powershell
docker compose config -q            # проверка файла (ничего не печатает при успехе; секреты не выводите командой без -q)
docker compose up -d --build        # первая сборка 5–10 минут
docker compose ps                   # backend и postgres должны быть healthy
```

Откройте **http://127.0.0.1:8088/**.

### 4.3. Пользователи

Демо-данные (временный пароль придумайте сами, не менее 12 символов):

```powershell
$env:DEMO_PASSWORD = 'придумайте-временный-пароль'
docker compose run --rm -e APP_ENV=development -e ALLOW_DEMO_SEED=true -e DEMO_PASSWORD --entrypoint /app/seed backend
Remove-Item Env:DEMO_PASSWORD
```

Либо только системный администратор:

```powershell
$env:BOOTSTRAP_ADMIN_PASSWORD = 'придумайте-временный-пароль'
docker compose run --rm -e BOOTSTRAP_ADMIN_LOGIN=admin -e BOOTSTRAP_ADMIN_DISPLAY_NAME=Administrator -e BOOTSTRAP_ADMIN_PASSWORD --entrypoint /app/bootstrap-admin backend
Remove-Item Env:BOOTSTRAP_ADMIN_PASSWORD
```

Логины и сценарии — как в разделе 3.4.

> В Git Bash перед такими командами задайте `MSYS_NO_PATHCONV=1`, иначе путь `/app/seed` превратится в `C:/Program Files/Git/app/seed`.

### 4.4. Управление

```powershell
docker compose logs -f backend      # журнал backend (Ctrl+C — выйти)
docker compose stop                 # остановить, данные сохраняются
docker compose up -d                # запустить снова
docker compose down                 # удалить контейнеры, ДАННЫЕ ОСТАЮТСЯ в томах
docker compose down -v              # удалить контейнеры И ВСЕ ДАННЫЕ (необратимо)
```

Данные хранятся в именованных томах `schooldiarysvu_postgres-data` и `schooldiarysvu_files-data` и переживают `down`/`up`.

Обновление: `git pull`, затем `docker compose up -d --build` (сначала сделайте копию, раздел 5).

## 5. Резервная копия и восстановление

> Копия на том же диске не защищает от поломки диска. Периодически копируйте папку с копиями на внешний носитель или в другое место.

### Способ А

```powershell
deploy\windows\diary.cmd backup -Quiesce
```

С `-Quiesce` приложение на секунды останавливается — так БД и файлы вложений гарантированно согласованы. Без флага копия делается «на ходу»: база согласована внутри себя, но файлы могут оказаться чуть новее базы.

Результат — папка `.local\backups\diary-ГГГГММДД-ЧЧММСС\`: `database.dump` (формат pg_dump custom), `files.zip` (вложения), `manifest.json` (время, версия схемы, коммит, SHA-256 файлов). Папка публикуется атомарно (до завершения у неё суффикс `.partial`); хранится `DIARY_BACKUP_KEEP` последних копий.

Восстановление:

```powershell
deploy\windows\diary.cmd restore -Archive .local\backups\diary-20261031-201847
```

Скрипт проверяет контрольные суммы (при расхождении отменяет), просит ввести `YES`, **сохраняет текущее состояние** в `.local\backups\before-restore-…`, пересоздаёт базу, возвращает БД и файлы и запускает приложение. Сообщение «Восстановление завершено» выводится только после успешного `/health/ready`. После восстановления войдите и проверьте журнал и вложения.

Полное восстановление «с нуля» (например, после переустановки): `git clone` → `diary.cmd setup` → `diary.cmd start` → положить папку копии в `.local\backups\` → `diary.cmd restore -Archive …`. Пароли пользователей и данные берутся из копии.

### Способ Б

```powershell
deploy\windows\docker-data.cmd backup
deploy\windows\docker-data.cmd restore -Archive backups\docker-20261031-203924
```

Копии — в папке `backups\` (в `.gitignore`): `database.dump`, `files.tgz`, `manifest.json`. Логика такая же: проверка сумм, подтверждение `YES`, пересоздание БД, возврат файлов, запуск и ожидание готовности. Если у вас нестандартный `.env`, добавьте `-EnvFile путь`. Если порт не 8080, перед восстановлением задайте `$env:HTTP_PORT = '8088'` (скрипт ждёт готовности по этому порту).

## 6. Ручная проверка по ролям (чек-лист)

С демо-данными (вариант 1). Время — около 20 минут.

**Системный администратор (`demo-sysadmin`)**:
1. «Система»: состояние сервисов, загрузка процессора, памяти и диска, запросы в минуту и время ответа, подключения к БД, крупнейшие таблицы, нагрузка по маршрутам API.
2. «Администрирование → Структура»: учебные годы, периоды (закрытие, поздние правки), шкалы оценок, параметры школы. Обычному администратору здесь видны только классы, предметы и кабинеты.
3. «Пользователи» → «Добавить пользователя»: роль «Администратор» доступна только вам.

**Администратор (`demo-admin`)** — главная страница с показателями школы, затем «Администрирование»:
1. «Пользователи»: поиск, фильтры по роли, состоянию и классу; «Добавить пользователя» (логин подставляется из ФИО, пароль генерируется и показывается один раз, ученика можно сразу зачислить в класс). Для существующего пользователя: изменить ФИО и роли, сбросить пароль, завершить сеансы, деактивировать, затем вернуть через фильтр «Деактивированные». Административные учётные записи изменить нельзя.
2. «Импорт»: вставьте строки из Excel (`ФИО; роль; класс`), нажмите «Проверить», затем «Создать» и скачайте CSV с логинами и временными паролями.
3. «Приглашения»: код для родителя, связанный с ребёнком. Откройте ссылку в другом браузере, зарегистрируйтесь — родитель сразу видит ребёнка; повторно код не срабатывает.
4. «Зачисление»: массовое зачисление учеников и перевод класса целиком.
5. «Расписание»: недельная сетка класса (добавить, изменить, удалить урок), затем «Создать уроки» на период. Раздел «Расписание» в меню показывает расписание любого класса или учителя.
6. «Аудит»: действия с фильтрами.

**Учитель (`demo-teacher1`)**:
1. «Журнал» → период «I четверть», месяц `2026-09`. Выберите ячейку, нажмите цифру `5`, затем `Enter` — оценка сохранится, фокус перейдёт к следующему ученику. Стрелки двигаются по таблице, `Escape` закрывает редактор.
2. В редакторе откройте «История изменений» — видно, кто и когда менял оценку. «Отменить изменение» откатывает последнюю правку.
3. «Все присутствуют» и ручные отметки посещаемости под таблицей.
4. «Расписание» → кликните урок: вкладки «Урок / Журнал / Домашнее задание / История». Смените статус на «Завершён» — появится справочная проверка заполненности.
5. «Домашние задания»: создайте черновик, прикрепите файл (JPEG, PNG, GIF, PDF или обычный текстовый файл, до 10 МБ; Word и Excel не принимаются — это ограничение безопасности), опубликуйте, скопируйте на следующую неделю.
6. «Мой класс», «Отчёты» (скачайте CSV).

**Ученик (`demo-student1`)**: «Главная» (баннер, средний балл, посещаемость, ближайшие задания, графики по предметам и неделям), «Расписание», «Задания» (фильтры по сроку, личная отметка «выполнено» — она не является сдачей работы), «Оценки» (средневзвешенный балл с объяснением расчёта), «Объявления».

**Родитель (`demo-parent1`)**: в шапке переключатель «Ребёнок» (два ребёнка); при переключении данные первого ребёнка не должны оставаться на экране. Настройки → уведомления, сводка, тихие часы.

**Права доступа** (должны блокироваться сервером, а не только скрываться в интерфейсе): ученик не видит чужие оценки; родитель — только своих детей; учитель — только свои классы; скачивание файла без входа возвращает 401.

## 7. Автоматические проверки на вашем развёртывании (необязательно)

```powershell
cd web
npm ci
npx playwright install chromium          # один раз, скачивает браузер (или используйте установленный Edge, см. ниже)
$env:E2E_BASE_URL = 'http://127.0.0.1:8090'    # адрес вашего развёртывания
$env:E2E_DEMO_PASSWORD = 'тот же временный пароль, что в seed-demo'
$env:E2E_CHANNEL = 'msedge'                    # необязательно: запуск в Microsoft Edge без загрузки Chromium
npx playwright test
```

Сценарии проходят вход со сменой пароля, ввод оценок с клавиатуры, конфликт версий из двух сессий, посещаемость, домашние задания, права ролей, мобильный режим, доступность (axe) и администрирование. **Они изменяют данные**, поэтому запускайте их только на тестовой базе. Тесты рассчитаны на свежий **базовый** `seed-demo` (без `-Rich`) с тем паролем, который вы укажете в `E2E_DEMO_PASSWORD`: при первом входе они сами меняют временные пароли. Если вы уже меняли пароли демо-пользователей вручную, повторите `seed-demo` (он сбрасывает пароли и снова требует их смены).

Юнит-тесты и сборка: `cd web; npm run typecheck; npm run lint; npx vitest --run; npm run build`. Backend: `go test ./...` (для интеграционных тестов нужна пустая тестовая БД в `TEST_DATABASE_URL`).

## 8. Диагностика

| Симптом | Причина и решение |
|---|---|
| `doctor`: `Go не найден` / `Initdb не найден` | Установите по подсказке; перезапустите PowerShell. PostgreSQL в нестандартной папке — `$env:DIARY_PG_BIN`. |
| `setup`: `npm ci не смог заменить node_modules` (EPERM) | Файлы держит запущенный dev-сервер Vite или редактор. Остановите `npm run dev` и повторите. |
| `start`: `Сервер не стал готовым` | Смотрите `diary.cmd logs`. Типично: порт занят (`DIARY_HTTP_PORT`), БД недоступна (порт `DIARY_PG_PORT`). |
| `create-admin`: `an administrator already exists; bootstrap is disabled` | Бинарники собраны до появления роли системного администратора. Выполните `backup -Quiesce`, `setup`, `start` (раздел 3.7) и повторите `create-admin`: новая версия создаст системного администратора рядом с существующим обычным. Если команда отвечает `a system administrator already exists` — системный администратор уже есть, войдите под ним. |
| `unknown time zone` | Старая сборка. Выполните `git pull` и `setup` (часовые пояса теперь встроены в бинарники). |
| Страница входа открывается, а после входа «Сначала смените временный пароль» | Ожидаемо для нового пользователя: форма смены пароля откроется сама. |
| «Слишком много попыток входа» (429) | Ограничение защиты от подбора пароля. Подождите время из сообщения. |
| В журнале пусто | Выберите период «I четверть» и месяц `2026-09` (данные демо — сентябрь 2026). |
| 404 вместо страницы, белый экран | Нет `web\dist`. Выполните `setup`. |
| `seed-demo`: `Схема БД ещё не создана` | Сначала `diary.cmd start` (миграции применяются при старте). |
| `restore` зависает | Обновите скрипт (`git pull`); старая версия могла ждать пароль PostgreSQL. |
| Кракозябры в консоли | `chcp 65001` перед запуском или Windows Terminal. На работу не влияет. |
| Docker: `Cannot connect to the Docker daemon` | Запустите Docker Desktop и дождитесь «Engine running». |
| Docker: порт 8080 занят | Задайте другой `HTTP_PORT` в `.env` и выполните `docker compose up -d`. |
| Docker: долгий первый `up --build` | Скачиваются образы и зависимости; повторные сборки используют кэш. |
| Антивирус блокирует `server.exe` | Добавьте папку `.local\bin` в исключения или запускайте способ Б. |

Каждый ответ сервера имеет заголовок `X-Request-ID`; тот же идентификатор есть в `server.log` и в окне ошибки интерфейса («Код запроса») — по нему легко найти причину.

Коды в `server.log`: `4xx` (WARN) — ошибки клиента и отказы прав, `499` — вкладка/запрос закрыты браузером (не сбой), `5xx` (ERROR) — сбой сервера; причина пишется в `server.err.log` строкой `unhandled error`.

## 9. Доступ с телефона или другого компьютера (на свой риск)

По умолчанию сайт виден только на этом ноутбуке. Чтобы открыть его для устройств в той же сети Wi-Fi:

1. Способ А: в `.local\config.env` задайте `DIARY_BIND_ADDR=0.0.0.0`, затем `diary.cmd restart`. Способ Б: `BIND_ADDR=0.0.0.0` в `.env` и `docker compose up -d`.
2. Разрешите входящее подключение к порту в брандмауэре Windows (нужны права администратора), только для **частной** сети:
   `New-NetFirewallRule -DisplayName "Diary test" -Direction Inbound -Protocol TCP -LocalPort 8090 -Profile Private -Action Allow`
3. На телефоне откройте `http://IP-ноутбука:8090` (IP: `ipconfig`).

Помните: пароли и сессии передаются **без шифрования** (HTTP). Делайте это только в доверенной домашней сети, только с тестовыми данными, и удалите правило брандмауэра после проверки (`Remove-NetFirewallRule -DisplayName "Diary test"`). Для настоящей школы нужен профиль `https` — см. `docs/security.md` и `docs/network.md`.

## 10. Остановка и удаление

```powershell
deploy\windows\diary.cmd stop                 # способ А: остановить
deploy\windows\diary.cmd reset                # способ А: удалить ВСЕ локальные данные (копии в .local\backups остаются)
docker compose down -v                        # способ Б: удалить контейнеры и ВСЕ данные
Remove-Item -Recurse -Force .local, .env, backups   # убрать остатки (необязательно)
```

## 11. Что проверено

На Windows 11 Pro 10.0.26200 (PowerShell 5.1, Git Bash), Docker Desktop 29.2, Node.js 24.14, Go 1.26.10, PostgreSQL 17.6 (портативная сборка) и 18 (служба не использовалась):

- Способ А: `doctor`, `setup` с нуля, `start`, `seed-demo`, `create-admin`-путь (через переменные окружения), `status`, `logs`, `stop`, `restart`; 15 сценариев Playwright (включая администрирование, конфликт версий, мобильный режим, axe) против `http://127.0.0.1:8090`.
- Способ А, аварийное восстановление: данные + вложение → `backup -Quiesce` → «лишние» данные → `reset` → `setup` → `start` → `restore`: вернулись данные до копии и файл, данные после копии исчезли, вход работает, ответов 5xx в журнале нет.
- Способ Б: `docker compose config`, сборка четырёх образов, запуск (healthcheck), 14 сценариев Playwright через Nginx, загрузка и скачивание вложения (том принадлежит `nonroot`), сохранность данных после `down`/`up`, анонимное скачивание файла → 401, заголовки безопасности Nginx, PostgreSQL не опубликован на хост, `docker-data.cmd backup` + `restore` (маркер «до» вернулся, «после» исчез).
- Не проверялось: запуск на чужой машине без предустановленных Go/Node (команды `winget` приведены по документации, но не выполнялись заново), доступ из локальной сети, HTTPS-профиль, ARM-версии Windows.
