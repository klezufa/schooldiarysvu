# Архитектура

## Контекст и границы

Система обслуживает одну школу и работает без внешних облачных сервисов. Поток: **Browser → Nginx → Go modular monolith → PostgreSQL / private file volume**. Nginx отдаёт React и проксирует `/api/v1` и healthchecks. PostgreSQL — единственный источник учебной истины; файловый volume хранит только бинарное содержимое, метаданные находятся в БД.

Один сервер является единой точкой отказа. Резервные копии должны создаваться на другом устройстве; отказ диска, сервера или ошибка администратора не устраняются самой архитектурой.

## Роли и доступ

| Действие | Администратор | Учитель / классный руководитель | Ученик | Родитель | Руководитель |
|---|---|---|---|---|---|
| Учебная структура | управление | чтение связанных данных | связанные данные | данные детей | чтение |
| Оценки и посещаемость | без скрытого права изменения | только активные назначения | только свои, чтение | только детей, чтение | отчёты |
| Задания | без скрытого права | свои предметы/классы | свои + личная отметка | детей, чтение | — |
| Аудит | просмотр | история своих сущностей | — | — | предусмотренные отчёты |
| Закрытый период | только отдельное разрешение | только отдельное разрешение | — | — | — |

RBAC проверяет возможность действия, ABAC — доступ к конкретному UUID. Скрытие кнопки авторизацией не является.

## Модули

`authn`, `authz`, `academic`, `schedule`, `journal`, `attendance`, `homework`, `files`, `announcements`, `notifications`, `reports`, `audit`. Отдельный `cmd/worker` очищает устаревшие сессии и формирует внутренние daily/weekly-сводки с учётом часового пояса, тихих часов и защиты от повторной отправки; Redis не требуется.

## Зависимости

HTTP handler декодирует строгий JSON, проверяет структуру и вызывает service. Service проверяет инварианты, права, период и версии, открывает транзакцию. Repository на pgx/sqlc выполняет явный SQL и не принимает решений о правах. Критическая запись и allowlisted audit old/new выполняются в одной транзакции. Зависимости передаются конструкторами в `cmd/server`.

## Сессии

Случайный токен существует только в HTTP-only cookie; БД хранит SHA-256-хеш. Сессия имеет expiration, last_seen и revocation. Пароль хешируется Argon2id. CSRF обязателен для изменяющих запросов. При смене пароля остальные сессии отзываются.

## Данные и конкуренция

Версионированные golang-migrate миграции встроены в backend и применяются при его запуске до открытия HTTP-порта. Учебные даты — `date`, моменты — `timestamptz`, часовой пояс — настройка школы. Исторические записи архивируются. Оценки, посещаемость, уроки и задания имеют `version`; несовпадение возвращает 409. Конфликты времени проверяются в транзакции с advisory locks: обычный UNIQUE не предотвращает пересечения интервалов.

## Аудит

Только разрешённые поля old/new: значение, статус, версия, автор и технические идентификаторы. Пароли, токены, cookie, содержимое файлов и произвольные персональные данные запрещены. Триггер БД запрещает UPDATE/DELETE аудита.

## Файлы и резервное копирование

Файлы получают случайный storage key, находятся вне публичной static-директории и скачиваются после ABAC-проверки. Backup включает согласованный `pg_dump`, файлы, manifest и версию схемы. Для согласованности БД и файлов используется краткий maintenance/snapshot-режим; готовый архив публикуется атомарно и копируется на другое устройство. Restore проверяется на временном окружении до пилота.
