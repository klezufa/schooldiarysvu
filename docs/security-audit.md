# Аудит безопасности, пентест и нагрузка (1 ноября 2026)

Проверка перед эксплуатацией: производственная конфигурация (Docker Compose, Nginx, лимиты памяти) на школе
в 360 учеников, 360 родителей и 150 учителей (`DEMO_DATASET=load`). Атаки — через Nginx, как у внешнего клиента.
Итог: найдено и исправлено 9 проблем, из них одна критическая для доступности; повторный пентест — 144 из 144,
нагрузка 600 одновременных пользователей — без ошибок.

## Что проверено и устояло

- **Анонимный доступ**: все закрытые ресурсы → 401.
- **CSRF**: изменения без токена, с токеном другой сессии и выход без токена отклоняются.
- **Горизонтальный доступ**: ученик и родитель не получают оценки, дашборд, расписание, задания, отчёты и объявления
  чужого ученика (проверяется и код ответа, и отсутствие чужого идентификатора в ответе); учитель не видит и не меняет
  журнал, посещаемость, уроки, отчёты, оценки и файлы чужого класса; ученик не ставит себе оценки.
- **Вертикальный доступ**: учитель, ученик, родитель не вызывают функции администратора (пользователи, импорт,
  приглашения, аудит, зачисление, перевод, генерация и перенос расписания, параметры школы); администратор не трогает
  зону системного администратора (годы, закрытие периодов, шкалы, параметры, «Система»), не создаёт системного
  администратора ни напрямую, ни приглашением, не сбрасывает ему пароль, не меняет его роли и не выдаёт роль себе.
- **Инъекции**: SQL-полезные нагрузки в поиске и логине (весь SQL — параметризованный sqlc), обход пути, не-UUID в
  путях; HTML в имени пользователя хранится строкой, экранируется React, встроенные скрипты блокирует CSP.
- **Файлы**: HTML под видом PDF, исполняемые файлы отклоняются; опасное имя очищается; скачивание — `attachment`,
  `nosniff`, `no-store`, без внедрения заголовков; чужие файлы не скачиваются и не архивируются.
- **Сессии**: после входа выдаётся новый токен, подставленное значение не становится сессией (фиксация), cookie —
  `HttpOnly`, `SameSite=Lax` (и `Secure` в профиле https), после выхода токен не работает.
- **Перебор**: одинаковый ответ и время для неизвестного логина и неверного пароля; подмена `X-Real-IP` и
  `X-Forwarded-For` не обходит блокировку; во время блокировки не принимается даже верный пароль.
- **Заголовки и ограничения**: CSP без `unsafe-inline` для скриптов и с `frame-ancestors`, `X-Frame-Options`,
  `nosniff`, `Referrer-Policy`, `Permissions-Policy`; `TRACE` запрещён; `limit` ограничен 100; расписание — не больше
  92 дней; тело запроса — не больше 2 МиБ; вложенный JSON и `/health/ready` не дают 500 и не раскрывают внутренности.

## Принятые риски

- **`gosu` в официальном образе PostgreSQL** — 26 HIGH/CRITICAL в стандартной библиотеке Go внутри бинарника. Утилита
  только понижает права при старте контейнера и не работает с сетью и TLS. Следить за обновлением образа (Dependabot).
- **Инструменты разработки npm** — 14 умеренных (ReDoS в `minimatch` через eslint и др.). В сборку для браузера не
  попадают (`npm audit --omit=dev`: 0).
- **`golang.org/x/crypto`** — одна известная запись в модуле, код проекта её не вызывает (govulncheck).
- **Профиль `local-http`** — cookie без `Secure`, трафик открытым текстом; допустим только в изолированной сети или на
  пилоте (`docs/security.md`, предупреждение на странице «Система» и у администратора).
- **Порог 50 неудачных входов с адреса** — за общим NAT большого компьютерного класса теоретически достижим при
  массовых опечатках; тогда вход с этого адреса блокируется на 15 минут. Порог — константа в `address_limiter.go`.

## Не покрыто этим аудитом

Защита ОС сервера и SSH, физический доступ, социальная инженерия, сетевой DoS (это задача firewall и маршрутизатора,
`docs/network.md`), фаззинг разбора ввода, проверка TLS-конфигурации на публичном сертификате (TLS-профиль проверен
на этапе 5 с тестовым сертификатом). Рекомендуется до ввода в эксплуатацию: прогон `docs/installation.md` на чистом
сервере и повторный `security/pentest.py` на нём (на тестовой копии данных).

## Как повторить

```bash
# Стек и нагрузочные данные — load/README.md. Затем:
BASE_URL=http://127.0.0.1:8086 PASSWORD=<DEMO_PASSWORD> FIXTURES=.tmp/load/fixtures.json python -I security/pentest.py
.tools/bin/gosec -exclude-generated ./cmd/... ./internal/...
go run golang.org/x/vuln/cmd/govulncheck@latest ./cmd/... ./internal/...
cd web && npm audit --omit=dev
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:0.69.3 image --severity HIGH,CRITICAL <образ>
```

Пентест блокирует адрес на 15 минут (проверка password spraying): повторный запуск — после перезапуска backend
или через 15 минут. Только против тестового стека: скрипт создаёт пользователей и меняет пароли демо-администраторов.
