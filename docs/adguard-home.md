# AdGuard Home: имя дневника в школьной сети

Задача DNS — чтобы на всех устройствах школы имя дневника (`dnevnik.school.example` или `dnevnik.svu`)
указывало на внутренний IP сервера, например `192.168.10.20`. Остальные запросы идут через уже настроенные
upstream-серверы AdGuard Home, включая семейный фильтр. DNS не создаёт доверия к сертификату: о сертификате —
[https.md](https.md).

## 1. Перезапись DNS

В веб-интерфейсе AdGuard Home: **Фильтры → Перезапись DNS → Добавить перезапись DNS**.

| Поле | Значение |
| --- | --- |
| Домен | `dnevnik.school.example` — точное имя, без `*.` |
| Ответ | `192.168.10.20` |

Не используйте шаблон `*.school.example`: он перехватит и сайт школы, и почту. Если сервер получит адрес
IPv6, добавьте вторую перезапись с ним; иначе устройство с IPv6 может получить AAAA-ответ из публичной зоны
(если он там есть) и пойти мимо.

Для публичного домена (вариант Let's Encrypt) в публичной DNS-зоне A-запись дневника **не нужна**: Let's Encrypt
проверяет только TXT-запись `_acme-challenge`, а внутри школы имя разрешает AdGuard. Так адрес внутреннего
сервера не раскрывается в интернете.

## 2. Устройства должны спрашивать AdGuard

- DHCP школьной сети раздаёт IP AdGuard Home как единственный DNS-сервер (без «запасного» 8.8.8.8 —
  с ним устройства иногда спрашивают публичный DNS и не находят дневник).
- Браузеры с «безопасным DNS» (DNS-over-HTTPS) идут мимо AdGuard. На управляемых устройствах отключите это
  политикой: Chrome и Edge — `DnsOverHttpsMode=off`, Firefox — `network.trr.mode=5`. Firefox сам не включает
  DoH, если имя `use-application-dns.net` не разрешается: проверьте, что AdGuard отвечает на него NXDOMAIN.
- iCloud Private Relay на iPhone/iPad/Mac: Apple отключает его в сетях, где не разрешаются `mask.icloud.com`
  и `mask-h2.icloud.com` — заблокируйте эти два имени в AdGuard («Пользовательские правила»:
  `||mask.icloud.com^` и `||mask-h2.icloud.com^`); пользователь увидит уведомление, что Private Relay в этой сети
  выключен.

## 3. Проверка

С компьютера и с телефона в школьной сети (Wi-Fi учителей, Wi-Fi учеников — там, где дневник должен работать):

```bash
nslookup dnevnik.school.example        # Address: 192.168.10.20, Server — IP AdGuard Home
```

В браузере `https://dnevnik.school.example` открывается без предупреждения. В **Журнале запросов** AdGuard
видно запрос с пометкой «Перезаписано».

Если `nslookup` показывает другой сервер или другой адрес — устройство получает DNS не от AdGuard (DHCP,
ручная настройка, VPN, DoH). Если адрес верный, а браузер не открывает — проверьте firewall ([network.md](network.md))
и сертификат ([troubleshooting.md](troubleshooting.md)).

## Вне школы

Перезапись работает только внутри школьной сети. Из дома дневник недоступен — это решение по умолчанию:
сервер не опубликован в интернете. Если удалённый доступ нужен, используйте VPN школы (устройство получает
DNS AdGuard через туннель), а не проброс порта 443 на роутере.
